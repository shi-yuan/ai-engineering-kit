# 数据库规则

## 适用范围

修改表结构、Mapper、Repository、SQL、Model、DTO 映射、数据迁移、报表查询、导出查询时适用。

## 必须检查

- 表、字段、业务键、唯一键、索引。
- 查询条件是否改变历史查询范围。
- 更新条件是否承担并发控制、状态保护或乐观锁职责。
- `NULL`、空字符串、默认值和历史脏数据语义。
- 排序稳定性、分页方式、批量参数规模。
- 大表查询的数据量级、索引命中和慢 SQL 风险。
- 新增字段的默认值、回填、回滚和灰度兼容。
- Mapper XML、Model、DTO、导出字段是否一致。

## 禁止事项

- 不得仅因为 SQL 能执行就判定修改安全。
- 不得在未确认索引和数据量级时扩大查询范围。
- 不得删除或弱化承担 CAS/状态保护职责的更新条件。
- 不得把测试环境 DDL 当作生产 DDL 事实；冲突时标记待确认。

## Design 要求

涉及数据库变更时，Design 必须说明：

- 表和字段变化。
- 读写路径变化。
- 查询条件和更新条件变化。
- 历史数据兼容策略。
- 数据迁移和回滚方案。
- 性能和索引风险。

## Verification 要求

验证至少覆盖：

- 关键 SQL 是否符合预期条件。
- 新旧数据是否兼容。
- 边界值、空值、重复数据。
- 大表或批量场景的性能风险说明。
