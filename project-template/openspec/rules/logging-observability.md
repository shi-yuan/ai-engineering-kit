# 日志与可观测性规则

## 适用范围

修改核心业务链路、外部调用、状态变化、异步消费、Job、补偿、人工操作入口时适用。

## 必须检查

- 是否记录业务主键、外部流水号、请求 ID 或 trace ID。
- 状态变化是否有前后状态。
- 外部调用是否记录请求摘要、响应摘要、错误码和耗时。
- MQ Consumer、Job 是否记录重复执行和失败原因。
- 异常降级或吞异常是否有告警或补偿。
- 敏感信息是否脱敏。

## 关键写操作日志（必须）

新增、修改、删除、导入、提交、审批、作废、冲正等写操作，必须在关键流程节点记录日志：

- Service 写方法入口：记录操作类型、业务主键/单号、操作来源（人工/Job/回调/MQ/审批系统）。
- 写操作成功后：记录影响结果（影响行数、生成的单号、变更前后关键状态）。
- 删除、作废、冲正等破坏性操作：必须记录操作前数据关键字段快照和操作原因。
- 写操作失败：记录失败原因和已执行到的阶段，不得只抛异常不留日志。
- 批量写操作：记录总数与失败数量，失败明细按行或抽样记录。

## 代码审查联动

- code-review 对关键写操作缺失日志的情况按 P1 报告，不作为可选项。

## 禁止事项

- 不得记录密码、Token、密钥、身份证、手机号等敏感明文。
- 不得只打印“失败”而没有业务定位信息。
- 不得吞掉异常且没有任何可观测信号。

## Verification 要求

- 核心场景能通过日志定位业务单。
- 异常场景能通过日志定位失败阶段。
- 高风险链路需要明确告警或人工排查入口。
- 新增/修改/删除等写操作能通过日志还原操作轨迹（谁、何时、对哪条数据、做了什么、结果如何）。
