# 上下文健康规则

## 目的

控制 Agent 指令、项目规则和长期上下文的规模、层级和冲突，避免上下文膨胀导致遵循率下降。

## 加载层级

| 层级 | 内容 | 加载策略 |
|---|---|---|
| L0 全局执行规则 | `AGENTS.md`、`.agent-env.md`、`openspec/config.yaml`、`openspec/rules/change-gates.md` | 每次任务必须加载 |
| L1 当前变更事实 | 当前 `openspec/changes/<change-id>/` 下 artifacts | 当前 change 必须加载 |
| L2 相关长期上下文 | 与本次需求相关的 `project-context`、业务不变量、集成注册表 | 按需加载，必须记录已读范围 |
| L3 Path-specific 规则 | 与被修改目录、模块、接口、表、Topic、Job 相关的规则 | 仅修改对应范围时加载 |
| L4 历史参考 | 已归档 change、历史分析、非本次相关文档 | 默认不加载，必要时摘要化引用 |

## 必须遵守

- 新增长期上下文前，优先更新已有 registry 或规则文件。
- 每条长期事实必须带证据链接，例如代码路径、配置路径、DDL、SQL、接口文档、测试证据或人工确认记录。
- 同一事实不得在多个文件重复维护；如需引用，使用链接或 ID。
- 规则文件只写可复用约束，不写单次需求细节。
- `project-context` 只写已确认事实，不写未确认推断。
- 文档与真实代码冲突时，记录 Context Drift，以真实代码描述当前行为。

## 禁止事项

- 不得把所有 project-context 全量复制进 prompt。
- 不得把临时方案沉淀为永久规则。
- 不得在 `AGENTS.md` 中堆叠模块细节、接口细节或一次性需求细节。
- 不得保留互相冲突的规则而不标注优先级。

## 健康检查

执行 `scripts/lint-kit.ps1` 或项目级等价检查时，应检查：

- 是否存在明显版本漂移。
- 必需 registry 是否存在。
- 关键模板是否存在必填章节。
- 是否仍包含过期 Kit 版本号。
- 是否存在未处理的 Context Drift 占位项。
