# 金额与核心数值规则

## 适用范围

涉及金额、余额、额度、库存、积分、计费、授信、清结算、手续费、分润、税费、退款、冲正、冻结、解冻等核心数值变化时适用。

## 必须检查

- 内部单位和外部单位。
- 单位转换位置。
- 精度、舍入、截断和正负方向。
- 主单与明细合计关系。
- 金额、数量、额度是否允许为 0 或负数。
- 重复请求、重复回调、重复消费、重复 Job 是否会重复扣减或重复发放。
- 对账、报表、财务、客服、运营人工流程是否依赖该数值。

## Java 规则

- 金额优先使用 `BigDecimal`。
- 禁止用 `double` / `float` 表示金额。
- `BigDecimal` 数值比较使用 `compareTo`。
- 明确 `scale`、`roundingMode` 和格式化位置。

## 禁止事项

- 不得擅自改变金额单位。
- 不得把外部系统金额单位假定为内部单位。
- 不得用字符串拼接或隐式类型转换处理金额。
- 不得忽略终态保护导致重复扣款、重复退款、重复发放。

## Verification 要求

高风险数值变更必须覆盖：

- 正常值、0、最小值、最大值。
- 精度边界。
- 重复请求。
- 并发执行。
- 外部失败后补偿。
- 对账或报表口径。
