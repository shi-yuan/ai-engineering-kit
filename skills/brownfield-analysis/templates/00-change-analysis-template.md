# 00-change-analysis 模板

## 使用规则

历史功能修改必须先完成本模板，再进入 Proposal、Design 或 Apply。本文档是模板，不记录单次需求结论；每个变更应复制到 `openspec/changes/<change-id>/00-change-analysis.md` 后填写。

分析必须区分：

- 已确认事实：来自真实代码、Mapper、DDL、配置、运行环境证据或已确认文档。
- 合理推断：由调用链、数据流、状态变化、上下游关系推得，但尚未被运行态或完整链路验证。
- 待确认问题：需要业务方、生产配置、真实库、MQ 控制台、RPC 注册中心、外部系统或历史负责人确认。

不得只根据类名、方法名、字段名、单个 SQL 或局部代码确认业务语义。

## 通过标准

完成的 `00-change-analysis.md` 必须满足：

- 至少覆盖一个完整正向调用链和一个反向影响分析。
- 涉及高风险核心动作时必须写清业务不变量、单位、幂等键、状态保护和失败收敛。
- 涉及数据库时必须列出表、字段、查询条件、更新条件和索引影响。
- 涉及 RPC/MQ/Job 时必须列出 Provider/Consumer、Producer/Consumer 或任务入口。
- 待确认问题不能被写入 Proposal 作为已确定设计前提。
